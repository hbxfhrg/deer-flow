# 业务需求

（添加PRD链接：——）

**业务描述**：场景设定是对练系统的核心配置模块，用于管理不同的练习场景。每个场景包含场景名称、描述、练习模式、知识库内容、摘要提取、评分规则等配置。用户可以通过可视化界面创建、编辑、删除和启用/禁用场景，为AI对练提供基础数据支撑。

**核心功能**：

1、**场景CRUD**：支持创建、查看详情、更新、删除（软删除）、启用/禁用场景

2、**练习模式配置**：支持"剧本式"和"自由式"两种模式
   - 剧本式：按预设剧本进行对练
   - 自由式：需要配置知识库和评分规则

3、**知识库管理**：支持输入和编辑场景关联的知识库内容

4、**AI摘要提取**：调用大语言模型自动从知识库内容中提取结构化摘要
   - 输出格式：`维度名称：要点详情`（每行一个维度）
   - 支持自定义提示词模板
   - 自动解析分类标签

5、**评分规则配置**：支持手动配置或AI自动生成评分规则
   - 格式：`维度名称：分值`
   - 支持多维度权重分配

6、**考核范围选择**：支持多选考核分类标签

**数据质量要求**：

1、自由式模式必须填写知识库内容和评分规则

2、场景名称不能为空

3、评分规则总分建议为100分

4、摘要文本格式必须符合"维度：要点"格式

**运维管理要求**：

1、删除操作采用软删除，仅修改status字段

2、需要记录创建人、创建时间、更新时间

3、建议定期备份场景数据

```sql
CREATE TABLE `pract_scene_set` (
  `scene_id` INT AUTO_INCREMENT PRIMARY KEY COMMENT '场景ID',

  `scene_description` VARCHAR(500) COMMENT '场景描述',

  `model_name` VARCHAR(128) DEFAULT 'gpt-4o-mini' COMMENT '大模型名称',
  `system_prompt` TEXT COMMENT '系统提示词',
  `user_prompt_template` TEXT COMMENT '用户提示词模板',
  `metadata_json` JSON COMMENT '元数据JSON（含prompt_template）',
  `practice_mode` VARCHAR(20) DEFAULT '剧本式' COMMENT '练习模式：剧本式/自由式',
  `knowledge_base` TEXT COMMENT '知识库内容',
  `summary_text` TEXT COMMENT '摘要信息（格式：维度：要点）',
  `exam_categories` VARCHAR(200) COMMENT '考核范围（逗号分隔）',
  `scoring_rules` TEXT COMMENT '评分规则',
  `status` TINYINT DEFAULT 1 COMMENT '状态：1=启用，0=禁用',
  `create_by` VARCHAR(50) COMMENT '创建者',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  INDEX `idx_scene_name` (`scene_name`),

```

## 核心业务逻辑

### 场景创建逻辑
```
1. 验证必填字段（场景名称）
2. 自由式模式验证：知识库内容非空、评分规则非空
3. 处理驼峰转下划线命名
4. 处理 metadata_json 序列化
5. 保存到数据库
6. 返回创建结果
```

### 摘要提取逻辑
```
1. 接收知识库文本和可选提示词模板
2. 构建提示词（使用默认或自定义模板）
3. 调用大模型API提取摘要
4. 清理返回的markdown格式
5. 解析分类列表（按行分割，处理各种格式）
6. 返回结构化结果
```

### 默认摘要提取提示词模板
```markdown
你是一位专业的内容分析师，擅长将非结构化文本转化为清晰的结构化笔记。

请阅读以下提供的文本，并根据其内容执行以下操作：
1. **识别维度**：分析文本语义，自动归纳出文中的核心主题或分类维度
2. **提取要点**：在每个维度下，提取最关键的事实、数据、观点或结论
3. **精简表述**：去除口语化、废话和修饰性词语，保留核心信息。

**输出格式要求：**
- 采用"维度名称：要点详情"的格式
- 每个维度单独一行
- **仅输出结果**，不要包含解释

**待处理文本：**
{{TEXT}}
```

### 摘要解析函数（前端TypeScript实现）
```typescript
const parseSummaryLines = (text: string): { label: string; content: string }[] => {
  // 1. 清理markdown代码块
  let cleaned = text.replace(/```[\s\S]*?```/g, '').trim();
  
  // 2. 按换行分割
  let lines = cleaned.split('\n').map(l => l.trim()).filter(Boolean);
  
  // 3. 智能处理未换行情况（多个冒号分隔）
  if (lines.length === 1 && lines[0].includes('：') && lines[0].includes('。')) {
    const parts = lines[0].split('。').filter(p => p.trim());
    lines = parts.map(p => p.trim() + '。').filter(p => p.includes('：'));
  }
  
  // 4. 按第一个中文冒号分割
  return lines
    .filter(line => line.includes('：'))
    .map(line => {
      const colonIndex = line.indexOf('：');
      return {
        label: line.substring(0, colonIndex).trim(),
        content: line.substring(colonIndex + 1).trim()
      };
    })
    .filter(item => item.label && item.content);
};
```

### 自动生成评分规则逻辑
```typescript
const autoScoringRules = (summaryText: string): string => {
  const items = parseSummaryLines(summaryText);
  const weightPerDimension = Math.floor(100 / items.length);
  return items
    .map(item => `${item.label}：${weightPerDimension}分`)
    .join('\n');
};
```

## 注意事项

1、**字段命名转换**：前端使用驼峰命名，后端使用下划线命名，需做好转换

2、**JSON序列化**：metadata_json字段需正确序列化/反序列化

3、**软删除**：删除操作只修改status字段，不真正删除数据

4、**自由式模式校验**：必须同时提供知识库和评分规则

5、**摘要格式兼容**：需要处理LLM返回的各种格式（markdown、纯文本、无换行等）

6、**评分规则格式**：建议总分100分，维度之间可自定义权重
