# 自由式对练引擎开发方案

## 一、方案概述

基于 `pract_scene_set` 场景配置（知识库 + 考核维度 + 评分规则），实现 LLM 驱动的自由式对练。核心思路：用两次 LLM 调用驱动一轮对话——第一次扮演客户角色生成回复，第二次以教练身份对学员发言进行多维度打分。

### 整体架构

```
前端 ChatPage → useRoleplay hook → /api/roleplay/practice/start|turn|end
                                        ↓
                                  PracticeService
                                   ↙          ↘
                          LLM (客户角色)    LLM (评估打分)
                              ↓                ↓
                       pract_dialog_detail  pract_course_record
```

### 对练流程

```
用户进入 ChatPage → 点击"开始对练"
    ↓
POST /practice/start → 加载场景配置 → 创建 pract_course_record → LLM 生成客户开场白
    ↓
用户输入 → POST /practice/turn
    ↓
  保存用户话术 (pract_dialog_detail, speaker=1)
    ↓
  LLM 评估打分 (基于当前轮次考核维度 + scoring_rules + 对话历史)
    ↓
  写入 dialog_detail.score / .feedback
    ↓
  判断是否达到 total_rounds？
    ├─ 是 → is_complete=true，LLM 生成最终报告，更新 pract_course_record.summary
    └─ 否 → LLM 生成下一条客户回复（聚焦下一个考核维度）→ 存 DB (speaker=2) → 返回前端
    ↓
用户也可以随时手动点击"结束对练" → POST /practice/end → LLM 生成最终报告，更新 pract_course_record.summary
```

### 结束条件（方案 C）

- A：达到场景配置的总轮次后自动结束（总轮次 = exam_categories 维度数量）
- B：用户手动点击"结束对练"按钮
- **两者都支持**：轮数到达自动触发结束，用户也可随时提前结束

```sql
    dialog_id    BIGINT      NOT NULL AUTO_INCREMENT  COMMENT '对话 ID，主键',

    feedback     TEXT         DEFAULT NULL            COMMENT 'AI 对该句的即时反馈（仅学员发言有值）',
    create_time  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '发言时间',
    PRIMARY KEY (dialog_id),
    INDEX idx_record_id (record_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='对话详情表';
```

### 3.2 新建 `practice_service.py`

文件路径：`backend/packages/harness/deerflow/roleplay/practice_service.py`

```python
class PracticeService:
    """自由式对练核心引擎"""
    
    @staticmethod
    async def start(course_id: int, user_name: str) -> dict:
        """
        开始对练：
        1. 加载课程和关联场景配置
        2. 创建 pract_course_record（对练开始时创建）
        3. 计算总轮次（自由式对练取 exam_categories 维度数量）
        4. 构造客户角色 system prompt（场景摘要 + 背景描述 + 角色设定 + 本轮考察重点）
        5. LLM 生成开场白（聚焦第一个考核维度）
        6. 开场白写入 pract_dialog_detail（speaker=2）
        7. 返回 record_id + 开场白内容
        """
    
    @staticmethod
    async def turn(record_id: int, user_message: str) -> dict:
        """
        处理一轮对话：
        1. 查询 pract_course_record 和场景配置
        2. 检查对练是否已结束（end_time 不为空则拒绝继续）
        3. 动态计算当前轮次（统计学员回复数量）
        4. 学员话术写入 pract_dialog_detail（speaker=1）
        5. 获取当前对话历史
        6. LLM 评估打分（聚焦当前轮次考核维度）
           → 返回：round_score, dimension_scores, feedback
        7. 写入 dialog_detail.score / .feedback
        8. 判断是否完成（current_round >= total_rounds）
           ├─ 是 → 进入结束流程，生成最终报告，更新 pract_course_record.summary
           └─ 否 → LLM 生成下一轮客户回复（聚焦下一个考核维度）
        9. 客户回复写入 dialog_detail（speaker=2）
        10. 返回：customer_message, evaluation, is_complete, round
        """
    
    @staticmethod
    async def end(record_id: int) -> dict:
        """
        手动结束对练：
        1. 查询 pract_course_record 和对话历史
        2. 检查是否已结束（end_time 不为空则直接返回）
        3. 动态计算当前轮次（统计学员回复数量）
        4. LLM 生成最终评估报告（汇总各轮每维度评分取平均 + 优缺点 + 总结）
           → 返回：total_score, dimension_scores, strengths, improvements, summary
        5. 更新 pract_course_record：end_time, total_score, summary, accord_finish
        6. 返回完整报告
        """
    
    @staticmethod
    async def get_practice_history(record_id: int) -> list[dict]:
        """获取某次对练的完整对话历史（含评分）"""
    
    @staticmethod
    async def get_report(record_id: int) -> dict:
        """获取最终评估报告"""
```

### 3.3 轮次计算逻辑

#### 3.3.1 总轮次计算

```python
# 总轮次计算逻辑：
# - 自由式对练（practice_mode="text" 或 "自由式"）：取 exam_categories 字段中逗号分隔的类别数量
# - 其他模式：使用 dialog_round_limit 配置，默认 5 轮
if (scene.practice_mode == "text" or scene.practice_mode == "自由式") and scene.exam_categories:
    # 同时支持中文逗号和英文逗号分割
    categories = scene.exam_categories.replace("，", ",").split(",")
    total_rounds = len([cat.strip() for cat in categories if cat.strip()])
    if total_rounds == 0:
        total_rounds = 5
else:
    total_rounds = scene.dialog_round_limit or 5
```

#### 3.3.2 当前轮次计算

```python
# 动态计算当前轮次：AI开场白不算轮次，统计学员回复的数量即为当前轮次
current_round = 0
for d in all_dialogs:
    if d.speaker == 1 and d.content:  # 学员回复
        current_round += 1

# 在 turn 方法中，学员回复后，当前轮次 + 1（这才是真正的当前轮次）
# current_round += 1  # 仅在 turn 方法中执行
```

**关键点说明**：
- AI 开场白（speaker=2）不计入轮次
- 每收到一条学员回复（speaker=1），轮次加1
- 在 `turn` 方法中，写入学员回复后需要再 +1（表示当前正在处理的轮次）
- 在 `end` 方法中，直接统计学员回复数量即可（无需额外 +1）

#### 3.3.3 获取当前轮次考核维度

```python
def _get_current_category(scene: SceneRow, round_num: int, seed: int = 0) -> str:
    """根据轮次获取当前需要考察的考核维度（使用 seed 保证同一次对练维度顺序一致）"""
    if not scene.exam_categories:
        return ""
    
    # 解析考核维度（支持中英文逗号）
    categories = scene.exam_categories.replace("，", ",").split(",")
    categories = [cat.strip() for cat in categories if cat.strip()]
    
    if not categories:
        return ""
    
    # 使用 seed 进行确定性随机打乱（保证同一次对练维度顺序一致）
    if seed != 0 and len(categories) > 1:
        rng = random.Random(seed)
        categories = categories.copy()
        rng.shuffle(categories)
    
    # 根据轮次返回对应的维度（轮次从1开始）
    index = round_num - 1
    if index < len(categories):
        return categories[index]
    
    # 如果轮次超过维度数量，返回最后一个维度
    return categories[-1]
```

### 3.4 LLM Prompt 设计

#### 3.4.1 开场白专用 Prompt

```
系统角色：你正在模拟一位真实客户，正在进行一场对话练习。

【场景背景】
{scene_description}

【场景知识】
{summary_text}

【你的人物设定】
- 这是对话的开始，你需要先做自我介绍，然后提出问题
- 说话自然、口语化，避免 AI 味
- 自我介绍要简短亲切，说明你的身份（如：我是来买车的客户、我是面试者等）
- 自我介绍后，自然过渡到第一个问题
- 你的回复要简短，2-4句话即可
- **关键要求**：提出**开放性问题**，鼓励学员详细阐述

【本轮考察重点】：{current_category}
- 你的问题必须与此维度相关
- 提出与此维度直接相关的具体问题或疑虑

请根据以上设定，生成开场白。先做简短自我介绍，再提出第一个问题。只输出开场白内容，不要加任何前缀或说明。
```

#### 3.4.2 客户角色 System Prompt（对话中）

```
系统角色：你正在模拟一位真实客户，正在进行一场对话练习。

【场景背景】
{scene_description}

【场景知识】
{summary_text}

【你的人物设定】
- 说话自然、口语化，避免 AI 味
- 先回应对方上一条回答（简要总结或表达理解），再自然过渡到下一个问题
- 可以表现出犹豫、追问、表达疑虑或感兴趣
- 根据对方的回复自然地推进对话，保持对话连贯性
- 不要主动结束对话
- 你的回复要简短，2-4句话即可
- **关键要求**：提出**开放性问题**，鼓励学员详细阐述，不要问只能用"是"或"否"回答的问题

【当前对话轮次】：第 {round} / {total_rounds} 轮

【本轮考察重点】：{current_category}
- **硬性要求**：你的问题和对话内容**必须100%与此维度相关**，不允许谈论任何无关话题
- 你是来深入了解此维度的潜在客户，不是闲聊
- 提出与此维度直接相关的**具体、深入**的问题或疑虑
- 引导学员详细讲解、解释或推销此维度的特点、优势和价值
- 可以提出质疑、追问细节，促使学员充分展示专业知识
- 如果学员偏离话题，礼貌地将话题拉回到此维度上

例如，如果本轮考察"三电系统"，你可以问：
- "你能详细介绍一下这款车的电池技术吗？续航表现如何？"
- "充电速度怎么样？支持哪些充电方式？"
- "电机的动力性能如何？加速表现怎么样？"

例如，回应学员回答后再提问：
- 学员说："我们的车续航里程很长。"
- 你可以回答："续航长确实是个重要优势，能具体说说在不同路况下的实际表现吗？"

请根据以上设定，生成你对学员上一句话的回复。先简要回应，再提出相关问题。只输出回复内容，不要加任何前缀或说明。
```

### 4.3 重写 `useRoleplay.ts`

核心改动：
- **删除**：thread/run/SSE 相关的所有代码
- **替换为**：直接调用 `api.practice.start/turn/end` 的普通 HTTP 请求
- **消息管理**：前端本地维护 message 数组（role='user'/'assistant'）
- **评估管理**：每轮 turn 响应中携带 evaluation，直接更新
- **轮次管理**：后端返回当前轮次，前端直接显示

```typescript
export function useRoleplay(courseId: number | null) {
  const [messages, setMessages] = useState<Message[]>([]);
  const [recordId, setRecordId] = useState<number | null>(null);
  const [isLoading, setIsLoading] = useState(false);
  const [isTyping, setIsTyping] = useState(false);
  const [currentRound, setCurrentRound] = useState(0);
  const [totalRounds, setTotalRounds] = useState(0);
  const [evaluation, setEvaluation] = useState<Evaluation | null>(null);
  const [report, setReport] = useState<EvaluationReport | null>(null);
  const [isComplete, setIsComplete] = useState(false);
  const messagesEndRef = useRef<HTMLDivElement>(null);

  // initConversation: 调用 api.practice.start
  const initConversation = useCallback(async (userName: string) => {
    if (!courseId) return;
    setIsLoading(true);
    try {
      const res = await api.practice.start(courseId, userName);
      setRecordId(res.recordId);
      setTotalRounds(res.totalRounds);
      setCurrentRound(1);
      const aiMsg: Message = {
        id: `ai-${Date.now()}`,
        role: 'assistant',
        content: res.customerMessage,
        createdAt: new Date().toISOString(),
      };
      setMessages([aiMsg]);
    } catch (e) {
      console.error('Failed to start practice:', e);
    } finally {
      setIsLoading(false);
    }
  }, [courseId]);

  // sendMessage: 调用 api.practice.turn
  const sendMessage = useCallback(async (content: string) => {
    if (!recordId || isLoading || content.trim() === '' || isComplete) return;
    
    const userMsg: Message = {
      id: `user-${Date.now()}`,
      role: 'user',
      content: content.trim(),
      createdAt: new Date().toISOString(),
    };
    setMessages(prev => [...prev, userMsg]);
    setIsLoading(true);
    setIsTyping(true);

    try {
      const res = await api.practice.turn(recordId, content.trim());
      
      // 更新评估
      if (res.evaluation) {
        setEvaluation({
          round: res.round,
          totalScore: res.evaluation.roundScore,
          dimensionScores: res.evaluation.dimensionScores,
          strengths: [],
          improvements: [],
          summary: res.evaluation.feedback,
        });
      }
      
      // 客户回复
      if (res.customerMessage) {
        const aiMsg: Message = {
          id: `ai-${Date.now()}`,
          role: 'assistant',
          content: res.customerMessage,
          createdAt: new Date().toISOString(),
        };
        setMessages(prev => [...prev, aiMsg]);
      }
      
      setCurrentRound(res.round);
      
      if (res.isComplete) {
        setIsComplete(true);
        if (res.report) setReport(res.report);
      }
    } catch (e) {
      console.error('Failed to send message:', e);
    } finally {
      setIsLoading(false);
      setIsTyping(false);
    }
  }, [recordId, isLoading, isComplete]);

  // endPractice: 调用 api.practice.end
  const endPractice = useCallback(async () => {
    if (!recordId) return;
    setIsLoading(true);
    try {
      const res = await api.practice.end(recordId);
      setIsComplete(true);
      setReport(res.report);
    } catch (e) {
      console.error('Failed to end practice:', e);
    } finally {
      setIsLoading(false);
    }
  }, [recordId]);

  return {
    messages, isLoading, isTyping, evaluation, report,
    isComplete, currentRound, totalRounds,
    initConversation, sendMessage, endPractice, messagesEndRef,
  };
}
```

### 7.1 数据库设计变更

## 八、智能错误处理机制

### 8.1 问题背景

在对练过程中，LLM（大语言模型）可能返回格式不正确的 JSON 数据，导致解析失败。为确保系统稳定性，后端实现了**智能环形重试机制**。

### 8.2 重试策略

**每轮按优化后的顺序执行修复策略，最多走3轮：**

```
基础解析失败
    ↓
识别错误类型（如：missing_quote）
    ↓
获取优化策略顺序（如：llm_regen → llm_fix → py_fix）
    ↓
第1轮：按顺序执行策略
    ↓ (全部失败)
第2轮：按顺序执行策略
    ↓ (全部失败)
第3轮：按顺序执行策略
    ↓ (全部失败)
返回错误提示："程序出错了，请稍后再试。"
```

### 8.3 错误类型识别

| 错误类型 | 识别特征 | 说明 |
|----------|----------|------|
| `missing_quote` | `property name`、`double quote` | 键名缺少引号 |
| `missing_comma` | `expecting ','` | 缺少逗号分隔符 |
| `missing_bracket` | `unexpected end of json` | 缺少闭合括号 |
| `format_mess` | `invalid`、`multiple` | 格式混乱 |
| `content_empty` | `null`、`empty` | 数据为空 |
| `unknown` | 其他 | 无法识别的错误 |

### 8.4 智能步骤排序

**策略成功率配置**：
```python
_REPAIR_STRATEGY_SUCCESS_RATES = {
    "py_fix": 0.75,    # Python代码修复成功率
    "llm_fix": 0.85,   # LLM格式修复成功率
    "llm_regen": 0.9,  # LLM重新生成成功率
}
```

**排序算法**：
1. 根据错误类型获取推荐策略列表
2. 结合成功率进行二次排序
3. 按成功率从高到低执行

### 8.5 核心函数

| 函数名 | 功能说明 |
|--------|----------|
| `_classify_json_error` | 识别 JSON 解析错误类型 |
| `_get_optimized_strategy_order` | 根据错误类型和成功率生成最优策略顺序 |
| `_fix_json_with_code` | Python 代码修复：修复缺引号、缺逗号、缺括号等 |
| `_fix_json_format` | LLM 格式修复：将报错 JSON 送入 LLM 修复 |
| `_regenerate_json` | LLM 重新生成：将完整会话送入 LLM 重新生成 |

```python
async def delete(course_id: int) -> dict:
    """物理删除课程记录"""
    async with async_session() as session:
        # 删除关联的对练记录
        await session.execute(
            delete(PractCourseRecord).where(PractCourseRecord.course_id == course_id)
        )
```

## 十九、JSON 解析智能重试机制

### 19.1 功能说明

处理 LLM 返回格式不正确的 JSON 数据，实现智能环形重试。

### 19.2 重试策略

每轮按优化后的顺序执行修复策略，最多走3轮：

1. **Python代码修复**：修复缺引号、缺逗号、缺括号等语法错误
2. **LLM格式修复**：调用 LLM 修复格式错误的 JSON
3. **LLM重新生成**：调用 LLM 重新生成完整的 JSON

### 19.3 错误类型识别

| 错误类型 | 识别特征 |
|----------|----------|
| `missing_quote` | property name、double quote |
| `missing_comma` | expecting ',' |
| `missing_bracket` | unexpected end of json |
| `format_mess` | invalid、multiple |
| `content_empty` | null、empty |

### 19.4 策略成功率
